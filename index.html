The work it saves you

Already connected for you

  • A Buy button that opens a secure checkout page hosted by Polar, the payment company.
  • A thank-you page buyers return to after paying.
  • A payment notification receiver: when Polar confirms a payment, the app checks the message is genuine and records that the buyer has access.
  • Refunds remove access automatically.
  • Storage for those purchase records, using a free database from Neon or Upstash (a local file while you develop).
  • A one-line check your pages can use: "has this email paid?"

What you still build and decide

  • Your product itself: the tool, download, course or feature people pay for.
  • How customers sign in (no login system is included).
  • Which pages or features are unlocked, and what they look like.
  • Your design, text, prices, terms and refund policy.
  • Creating your accounts, testing and launching.
  • Subscriptions: the kit handles one-time purchases only.

Your customer's side

Your side, as the builder

You fill in a settings file. These are your own accounts' values, kept out of your code (this is the kit's real template):

POLAR_ACCESS_TOKEN=        # from your Polar account
POLAR_WEBHOOK_SECRET=      # from Polar's notification settings
POLAR_ENVIRONMENT=sandbox  # switch to production when ready
POLAR_SUCCESS_URL=https://your-site/success
NEXT_PUBLIC_POLAR_PRODUCT_ID=   # the product you created in Polar
DATABASE_URL=              # added for you when you connect Neon

What the app records after a payment (from the test above, email shortened):

{ "email": "buyer@…",
  "productId": "442dee7f-…",
  "orderId": "aba67850-…",
  "active": true }      ← after the refund: false

Your own pages ask "does this email have an active purchase?" to decide what to show.

From purchase to launch, in plain English

  1. Get the template. After you buy, you get read access to the private code repository on GitHub (a free GitHub account is needed). You copy it to make your own.

  2. Open it in a code editor, such as VS Code or Cursor. You'll also install Node.js (free) to run it on your computer.

  3. Customize it. Change the text and design and add your product. This is where coding is needed. An AI coding assistant (in Cursor, Copilot, Claude Code and similar tools) can explain the code and make changes for you, but you still need to review what it changes and test it.

  4. Connect your accounts: GitHub for the code, Vercel to host the site, Polar to take payments, and a database (Neon or Upstash) to store purchases. You create these yourself and paste their values into the settings shown above.

  5. Test checkout and access in Polar's sandbox with a test card: buy, confirm access is granted, refund, confirm access is removed.

  6. Publish. Switch Polar to live mode, review your prices, terms and refund policy, and put the site online.

This is not no-code. Comfort with a code editor, a terminal and copying settings helps. If that's new to you, budget time to learn it with an AI assistant, or get help from a developer.

What has been tested, and what hasn't

  • Oct 12, 2026: the code type-checks, lints and builds. The app accepts genuine payment notifications and rejects tampered ones. Asking for checkout creates a real Polar sandbox checkout.
  • Oct 13, 2026 (12:03 AM MT): a full sandbox purchase with Polar's test card, shown in the screenshots above: checkout completed and returned to the thank-you page. The paid-order notification was signed with the real order data and sent to the app on the same computer, and the purchase was recorded. The order was then refunded in Polar's sandbox, and access switched off.
  • Not yet tested: Polar delivering notifications to a deployed copy over the internet (they were sent locally, because Polar can't reach a home computer), the Upstash Redis storage option, live payments, and GitHub access delivery to real buyers.

For developers

  • Stack: Next.js 16 (App Router, TypeScript), React 19, @polar-sh/nextjs. Deploys to Vercel.
  • Checkout: GET /api/checkout?products=<id> redirects to a Polar checkout session. Polar API errors return a JSON 502.
  • Webhooks (the "payment notifications" above): POST /api/webhook/polar, verified with Standard Webhooks or legacy Polar HMAC secrets. A bad signature gets a 403. Handles order.paid (grant) and order.refunded (revoke).
  • Entitlements (purchase records): grant(), revoke(), hasAccess(email, productId?). The backend is picked automatically: Upstash Redis, Neon Postgres, or a local JSON file (dev only, refused on Vercel).
  • Not included: auth, gated UI, subscription events, emails, admin dashboard.
  • Audit: npm audit --omit=dev reports 0 vulnerabilities. Dev-only lint tooling has known advisories with no upstream fix yet.

Glossary (optional)

Merchant of record (MoR)
The company that legally sells to your customer, collects payment, handles sales tax/VAT, invoices and refunds. For this kit that's Polar Software, Inc.
Polar
A payments company for software creators (polar.sh) that acts as merchant of record. It has a free sandbox for testing.
Webhook (payment notification)
An automatic message Polar sends your app, for example "order paid". It's signed with a secret so your app can tell it's genuine.
Entitlement (purchase record)
A saved record that a customer paid and should have access.
Sandbox
Test mode with fake money. Sandbox orders are never real revenue.
Repository (repo)
A folder of code stored on GitHub, with its history.
